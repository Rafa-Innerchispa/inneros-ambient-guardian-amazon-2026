# Atlas: fresh summaries and routine-mail batching

The owner-requested policy speaks one rotating summary every twenty minutes during the existing 08:00-22:00 Ecuador daytime window: Home, Bellini, Servers. Home alternates WiFi and camera/alarm coverage alongside energy; server detail rotates service state, resources and endpoint probes. Only source readings dated within five minutes qualify for spoken current-state claims. Missing evidence is announced as unknown. Critical findings and the existing immediate power/Bellini sentinels retain their emergency paths.

Ordinary [Correo/...] tasks entering running/completed states are accumulated durably by task ID in the existing local notification SQLite database instead of individually spoken. A server summary may include their last-hour aggregate at most once an hour, stating that task status does not verify email delivery. Failed/blocked tasks, requests for approval, and non-routine SMTP repairs are not filtered. No coordination task, approval scope, Telegram decision or execution authority is changed.

Muse's multi-Echo configuration is retained. Its prior announcement changes are preserved in a separate Git commit and private pre-deployment snapshots; private raw titles and full task IDs are excluded from speech. Other live Muse files remain untouched. A wholly failed speech submission retains the persisted outbox for retry; suppression is not delivery. Notification history records the actual submitted spoken text and source timestamps. Provider acceptance is not proof that a person heard the speaker.

No external model inference is used. Tests cover restart-safe grouping, exception paths, approval/failure events, source age, rotation, critical interruptions, mail rate limiting, speech bounds, and spoken evidence. Deployment preserves runtime hashes, snapshots both SQLite databases consistently, restarts only the two notification workers, and validates active source hashes and service state. Release evidence identifies backup and rollback; no gateway, VoiceOps, controller or authorization-worker restart is needed.
