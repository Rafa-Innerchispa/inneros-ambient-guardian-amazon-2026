# Judge Demo — no physical device required

This is the canonical hackathon demo path for InnerOS Ambient Guardian.

## Truth labels

- **REAL:** Ambient Guardian backend and policy state.
- **REAL:** official MCP Python SDK v2 over Streamable HTTP at `/mcp`.
- **REAL:** bounded prepare / separate human approval / verification evidence flow.
- **REAL when configured:** local Qwen/vLLM reasoning path.
- **SIMULATED:** Alexa+ voice experience in the browser.
- **SIMULATED:** Ring-compatible event source used for the demo.
- **OPTIONAL / NOT REQUIRED:** physical Echo and physical Ring devices.

The demo must never imply that the browser is a physical Echo or that the Ring-compatible simulator is a bound Ring device.

## Three reproducible judge scenarios

### 1. Home status

Click **1. Home status**.

Expected flow:

1. The UI resets the demo state.
2. The simulated Alexa+ utterance asks: `Is everything okay at home?`
3. Ambient Guardian reads property status and recent events.
4. The response is generated by local Qwen/vLLM when configured, otherwise the deterministic local fallback.
5. No action is prepared and no evidence receipt is created.

Acceptance: read-only, no physical effect.

### 2. What happened at 3 AM?

Click **2. What happened at 3 AM?**.

Expected flow:

1. Three Ring-compatible demo events are inserted at 03:04, 03:07 and 03:11.
2. The simulated Alexa+ utterance asks: `What happened at 3 AM?`
3. Ambient Guardian reconstructs the bounded time window using the real normalized event pipeline.
4. The result is persisted as a Home Flight Recorder / Incident Receipt with immutable incident ID and SHA-256 digest.
5. The receipt remains recoverable in a later session; no action is executed.

Acceptance: temporal event reconstruction works, the Ring edge remains truthfully labeled SIMULATED, and the incident receipt is durable.

### 3. Prepare lock

Click **3. Prepare lock**.

Expected flow:

1. The simulated Alexa+ utterance asks to prepare locking the front door.
2. Ambient Guardian returns a one-time bounded proposal.
3. The proposal reports `executed=false`.
4. No verification evidence exists yet.
5. Only the separate human approval button can execute the bounded simulator action.
6. After approval, the action is independently checked and an Evidence Receipt is created.

Acceptance: the model can prepare but cannot approve or execute.

## Core safety statement

**No human approval, no physical action. No verification, no success claim.**

The MCP tool surface intentionally excludes any approval or execution tool. The human approval route is a separate application surface.

## Physical-device path after the hackathon

A physical Echo can later replace the simulated Alexa+ edge through Alexa+ MCP Toolkit when entitlement exists, or through a standard Alexa Skill wrapper using the same backend. A real Ring device/test account can replace `RingSimulatorAdapter` without changing the normalized event contract.
